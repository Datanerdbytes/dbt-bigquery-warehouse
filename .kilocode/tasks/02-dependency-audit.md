- Read the current repository `AGENTS.md` and applicable directory instructions. Its architecture, production safety, credentials, tests, and auth rules remain in force.
- Work only in this task's assigned Agent Manager worktree. The base is `integration`; verify the actual branch, upstream, base SHA, and clean starting state. Set the Agent Manager base explicitly rather than assuming it.
- Do not merge into `integration` or `main`, push, deploy, delete worktrees/branches, or change production settings. Commit reviewed task files and report ready for review.
- These are suspected issues to audit, not confirmed findings. Inspect actual source/configuration first. No-op findings need evidence and a report; do not invent a vulnerability or manufacture a fix.
- Ownership is a batch agreement, not a filesystem lock. Coordinate any out-of-scope edit before making it. Preserve unrelated edits; avoid repository-wide formatting.
- Never query production BigQuery, run ingestion/deployment, create real accounts, or expose credentials in verification. Use local fixtures/mocks and isolated outputs.

## Issue to Verify
Age alone does not establish a vulnerability. Audit the actual locked dependency graph, including transitive packages, and report advisory identifiers, affected versions, fix versions, environment markers, and runtime versus development scope.

## Requirements
1. Inspect Python 3.12, Node 22+, uv/npm setup, Docker dependency usage, and current CI. Use reproducible locked installation/export rather than auditing an unrelated global environment.
2. Run a supported Python advisory audit with `pip-audit` and an npm audit against `package-lock.json`. Do not feed `uv.lock` directly to a tool that does not support it. Export a compatible locked requirements/PEP 751 representation with the installed uv version or audit a verified synced environment. Document exact tooling versions, commands, selected dependency groups, platforms, and all exclusions.
3. Audit runtime and development/build dependencies, identifying the graph actually shipped in Docker. Network access to advisory/package registries is allowed; production resources are not. Treat registry/advisory failures as incomplete audits.
4. Produce a reproducible inventory/SBOM in a supported standard format (for example, CycloneDX). Use tooling that actually supports the input; record ecosystems covered and any gap. Keep temporary exports out of maintained source and avoid private index credentials in reports.
5. Apply the smallest compatible supported upgrades addressing confirmed findings. Preserve Dash/Flask/Supabase behavior and minimum/exact dependency constraints required by `AGENTS.md`. Regenerate locks with uv/npm, never by manually combining lock entries. Avoid blind `npm audit fix --force` or broad upgrades solely for recency.
6. Add a separate credential-free audit workflow in the owned new file. It must not deploy, access production, or require GCP/Supabase secrets. Use Python 3.12 and supported Node 22+, locked installs, explicit tool versions, minimum permissions, and auditable commands. No privileged PR trigger or executing untrusted PR code with secrets.
7. Default the npm CI failure threshold to high/critical; record all severities in the report. `pip-audit` findings fail its check unless there is an explicitly reviewed, documented exception. Do not equate pip-audit's exit policy with npm's severity filter. Scanner errors must fail visibly rather than being suppressed with unconditional success.
8. Report unfixed advisories or breaking-upgrade decisions as blockers. Do not add blanket ignores, silently suppress findings, or claim an audit guarantees absence of vulnerabilities.

## Acceptance Criteria
- Inventory/SBOM and before/after advisory results describe the actual locked graphs and coverage limits.
- Compatible fixes have reproducible manifests/locks and rebuilt tracked outputs where changed.
- A separate audit workflow performs repeatable checks without production credentials or deployment.
- Remaining findings/exceptions and audit availability are explicit; required regressions pass on the submitted commit.
